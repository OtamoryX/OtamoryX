# 个性化漫画净化与推荐设计

**状态**: 产品方案；P8-6 推荐洞察只读首片已落地
**关联版本**: Phase 8 / v1.2.0+
**最后更新**: 2026-08-18

## 1. 背景与问题

OtamoryX 用户通过脚本持续下载合集，扫描后自动入库。合集中的漫画质量和题材差异很大，用户目前在随机栏中根据封面逐本判断，阅读几页后决定继续、退出或删除。

当前痛点不是删除动作本身，而是删除发生在阅读流程中，频繁打断寻找好作品的过程。用户的真实目标是提高随机栏打开后愿意继续阅读的比例，同时自动减少明确不喜欢的内容和磁盘占用。

现有“AI 自动标签”只描述内容，没有把内容理解、个人偏好、自动处置和行为反馈连接起来；平铺标签也无法表达“某标签只有与其他条件组合时才代表不喜欢”的情况。

## 2. 产品目标

### 2.1 核心目标

提高随机栏的有效阅读率：用户打开漫画后继续阅读达到设定页数的比例明显提高。

### 2.2 次要目标

- 入库后自动清理高置信度的不喜欢内容，降低磁盘增长速度。
- 让系统从删除、退出和持续阅读等自然行为中学习，不要求收藏、评分或额外打标签。
- 将 AI 推断转化为可解释、可纠正的个人规则。
- 在随机栏中保留一部分未知内容，支持探索和意外发现。

### 2.3 非目标

- 不建设需要用户定期处理的“待清理列表”。
- 不把黑白、全彩、篇幅等视觉或结构特征直接当作删除条件。
- 不以标签数量、自动删除数量作为唯一成功标准。

## 3. 核心用户流程

```text
文件入库
  -> 多页内容分析
  -> 结合个人偏好计算处置决策
  -> 高置信度内容静默移入回收站
  -> 其余内容进入偏好加权随机池
  -> 用户自然阅读
  -> 记录行为反馈
  -> 更新可解释规则与推荐权重
```

阅读过程中不弹出审核任务。对于漏网内容，提供“删除并显示下一本”的快捷动作，删除后立即继续浏览，并提供短暂撤销入口。

## 4. 内容理解

### 4.1 分析输入

每本漫画入库后异步抽取并分析：

- 封面。
- 开头、中段、结尾等位置的 8～20 张正文页。
- 文件名、目录名、已有元数据和标签。
- 页面中的 OCR 文本（模型或成本允许时启用）。

分析不阻塞扫描和阅读，任务可重试，失败时保留漫画并标记为待分析。

### 4.2 分析输出

AI 输出结构化内容概念，而不是只有平铺标签：

- 题材：异世界、游戏系统、同人、TS 等。
- 内容/视觉特征：全彩、黑白、篇幅、画风等。
- 每个概念的置信度、证据页和模型来源。
- 可组合的概念关系，支持“同人 + 游戏”这类条件。

黑白、全彩、胸部特征和页数只能作为排序或组合条件；除非用户规则明确，否则不能单独触发删除。

## 5. 个人偏好学习

### 5.1 行为信号

| 行为 | 默认信号 | 说明 |
|------|----------|------|
| 手动删除 | 强负反馈 | 明确不喜欢或不再需要 |
| 自动删除后恢复 | 强纠正信号 | 降低相关规则，记录例外 |
| 打开后快速退出 | 弱负反馈 | 不能单独触发自动删除 |
| 阅读达到阈值 | 正反馈 | 阈值按页数和总页数归一化 |
| 阅读至较后页 | 强正反馈 | 表示较高兴趣 |
| 重复打开/继续阅读 | 强正反馈 | 比单次打开更可靠 |
| 规则降权或删除 | 规则纠正 | 防止系统立即生成同一规则 |

系统从当前版本开始记录事件。已有历史数据不足时，使用用户访谈得到的初始偏好作为冷启动先验，并只对高置信度规则执行自动删除。

### 5.2 规则模型

系统生成可解释的加权组合规则，而不是固定黑名单。例如：

```text
异世界 + 游戏系统 -> 强负向
TS + 特定剧情类型 -> 自动删除候选
同人 -> 轻微负向，不单独删除
全彩 + 长篇 -> 推荐加权
```

规则页面支持：

- 调低重要程度。
- 删除整条规则。
- 查看触发条件、置信度、证据和近期命中数量。
- 查看和管理自动生成的例外条件。

用户纠正后，系统应继续观察并增加条件拟合偏好，不能立即恢复原规则。

## 6. 自动清理

### 6.1 决策分层

每本漫画进入以下之一：

1. **自动删除**：内容题材识别和个人负向偏好均达到高置信度。
2. **保留并降低推荐**：存在负向信号，但证据或个人偏好不足。
3. **保留并优先推荐**：与正向偏好高度匹配。

快速退出或单一弱标签不能单独触发删除。系统宁可保留不确定内容，也不应因为“黑白”等单一特征误删。

### 6.2 删除与恢复

- 自动删除静默执行，不打断阅读。
- 文件进入临时回收站，建议保留 14 天后彻底删除。
- 主界面仅显示“本周自动清理 N 本”等低干扰统计。
- 回收站记录删除原因、规则版本、模型置信度和来源页面。
- 恢复操作恢复文件和数据库记录，并作为强纠正信号。

## 7. 偏好加权随机

随机栏不再使用等概率随机，而是按个人偏好加权抽样：

- 约 75% 为高概率喜欢的内容。
- 约 25% 为未知内容或新组合，用于探索。
- 已达到自动删除条件的内容不进入随机池。

探索比例应可配置，并可根据有效阅读率和重复命中情况动态调整，避免推荐范围逐渐收窄。

## 8. 用户界面

### 8.1 偏好规则页

展示系统推断的规则、权重、置信度、证据和命中统计。主要操作为“降权”和“删除规则”，不引入评分系统。

### 8.2 自动清理记录

提供低干扰的清理统计和按原因查看能力。默认不要求用户审核；用户发现误删时，可以从回收站恢复。

### 8.3 随机阅读页

保留快速删除并进入下一本的操作，删除不弹确认框，使用短暂撤销提示防止误触。

## 9. 数据与服务边界

建议新增以下概念：

- `content_analysis`: 分析任务、模型、抽样页、结构化概念和置信度。
- `user_behavior_event`: 打开、翻页、退出、删除、恢复、规则纠正等事件。
- `preference_rule`: 用户级组合条件、权重、状态、来源和版本。
- `archive_disposition`: 保留、降权、自动删除、恢复等决策记录。
- `trash_entry`: 临时回收站文件、到期时间和恢复信息。

AI 服务通过统一适配层接入本地模型或云端模型，内容分析、偏好学习、自动清理和推荐排序分别可重试、可观测。

## 10. 成功指标与风险

### 10.1 指标

- **核心**：有效阅读率 = 打开后继续阅读达到阈值的漫画数 / 随机栏打开总数。
- 随机栏每 100 次打开中的手动删除次数。
- 自动删除恢复率。
- 入库后自动清理数量和磁盘增长速度。
- 分析任务成功率、延迟和模型成本。

### 10.2 主要风险

- 题材识别错误导致误删：使用多页抽样、置信度阈值、回收站和恢复反馈缓解。
- 行为样本不足导致过早推断：弱信号不触发删除，规则需要组合证据。
- 模型成本或处理延迟过高：分析异步化、缓存结果、支持本地模型和分级抽样。
- 推荐越来越窄：固定探索比例并监控题材覆盖率。
